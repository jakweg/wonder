# `barbet` Agent Guidelines

## Naming & Code Style
- **No abbreviations in domain/API names:** Spell out enum members, store fields, function parameters, and shader attribute/varying names in full (e.g. `AnimationId`, `animationStartTick`, `previousDirection`, `positionXZ` — not `AnimId`, `animStartTick`, `prevDir`, `posXZ`).
- **Activity handler parameter naming:** Use `self: EntityId` for the acting entity in activity/behavior modules (`push`, `tryPush`, `perform`, `onInterruption`, `onChildFinished`, `onAbort`), and `entityId` in generic store/runner APIs.
- **Keep idiomatic short locals:** Standard short names are fine and preferred for typed-array views (`f32`, `u32`, `u16`, `u8`), vector/transform components (`x`, `y`, `z`, `sx`, `sy`, `sz`, `tx`, `ty`, `tz`, `nx`, `ny`, `nz`), and `impl` (`const impl = globals.createGpuResources(spec)`).
- **Avoid redundant indirection and state:**
  - Access `game.entities2`, `game.world`, and `elementOffsets.<attr>` directly instead of creating one-off local aliases or destructuring-with-renames (`const { entityId: offsetEntityId } = ...`).
  - Prefer `Math.min` / `Math.max` over manual comparison ternaries, and prefer clear composite getters (`const { x, z } = game.entities2.getPosition(entityId)!`) over split scalar calls when readability benefits.
- **Clean types without call-site casts:**
  - Avoid `as (...)` function casts at call sites; type shared defaults (`defaults.ts`) and generic containers (`ActivityFrame<S = any>`) so generated union dispatchers infer clean callable signatures.
  - Prefer explicit nullable parameters (`result: ActivityResult<Id>`, defaulting to `null`) over conditional rest-tuple varargs, and convert `EntityId` with `entityId_asUint32(id)` when writing `Uint32Array` buffers.
  - Normalize unsigned 32-bit ticks with `>>> 0` (e.g. `SLEEP_INDEFINITELY = 0xffff_ffff`) so values stay non-negative JS numbers, and return `-1` from caller-allocated `Uint32Array` drain helpers when `out.length` is too small.
- **Formatting:** Follow `.prettierrc.json` (no semicolons, single quotes, trailing commas, `printWidth: 120`, `arrowParens: 'avoid'`). Note that `tsconfig.json` targets `es2024`.

## ECS (`src/main/game-state/new-entities/`)
- **Shared vs. archetype-specific stores:** Only create a generic store (e.g. `position.ts`, `facing.ts`) when the exact representation is reusable across multiple `EntityKind` archetypes (such as slimes, units, and animals). Put archetype-specific state and enums in `<kind>-*.ts` stores (e.g. `slime-metadata.ts`, `slime-animation.ts`) with archetype-prefixed methods (`getSlime*` / `setSlime*`) so flat `mergeStores(...)` namespaces stay unambiguous.
- **Intrinsic stores vs. `ActivityStore` frames:** Keep ECS stores strictly for intrinsic entity properties. Store per-activity local state (`state`) on `ActivityFrame` stack entries in `ActivityStore` (`dataMaps`) rather than creating per-activity stores or fixed-depth byte arrays.
- **`dataMaps` serialization & renderer isolation:** Rely on `prepareStorage({ dataMaps })` default JSON clone serialization for plain objects instead of custom `encode`/`decode` codecs. Values stored inside `dataMaps` (including `ActivityFrame.state` and `Interruption` payloads) **must be plain JSON-convertible data and must never hold references to other game objects or form cyclic reference loops** (store `EntityId` numbers/primitives instead). Guard top-level `dataMaps` init code with `if (map instanceof Map)` (renderer receives a `Symbol`), and ensure transient runtime sets (e.g. `newlyInterrupted`) do not re-trigger already-deferred entries upon deserialization.
- **Strict enum typing:** Type store read/write signatures with their specific TypeScript enum (`SlimeAnimationId`, `SlimeColorId`, `Direction`) rather than `number`, and always pass named enum members (e.g. `SlimeAnimationId.Idle`, `Direction.PositiveX`) instead of magic `0` literals in `onEntityAllocated` and callers.

## Activities & Codegen (`src/main/game-state/new-entities/activities/`)
- **Namespace activity modules + `.2bc.json` dispatch:** Export individual functions (`push` / `tryPush`, `perform`, `onInterruption`, `onChildFinished`, `onAbort`, re-exporting defaults from `defaults.ts`) and import via `import * as ActivityName from '...'` rather than wrapper objects. Register enums and dispatch tables in `.2bc.json` (compiled via `../encytem/src/build/compile-enums.ts`) and never hand-edit generated files.
- **Dynamic cooperative interruptions & stack return:** Let `onInterruption` dynamically return `Handled`, `Defer`, or `AbortAndPassToParent` (unwinding children via `onAbort` and waking the parent with `wakeTick = 0`) rather than using static policies or `'ignore'` modes; deliver death cooperatively via `InterruptionType.Die`. Type child return payloads via `ActivityResultById` / `CompletedChild` (`finishedActivityId`).

## WebGL2 Rendering (`src/main/3d-stuff/`)
- **Derive strides and offsets from `layout`:** Never hardcode vertex or instance byte strides or manual typed-array offsets. Read `{ strideBytes, byteOffsets, elementOffsets }` from `impl.buffers.<bufferName>.layout` computed during `globals.createGpuResources(spec)`.
- **Keep `shaders.ts` declarative:** Declare buffer specs cleanly (`{ dynamic: true }` / `{ dynamic: false }`) with inline program `attributes` rather than importing entity max-count constants or computing `initialBytesCapacity` inside `shaders.ts`. For dynamic buffers rewritten from offset `0` each frame, prefer `setContent(...)` unless fixed-capacity `setSize(...)` + `setPartialContent(...)` is specifically needed for large instance counts.
- **Shader time & world-space motion:** Use `GameTickUniform` for simulation-driven animations and `RenderTimeUniform` (`u_gameTimes.x`) for animations that must keep running while paused. Apply tile-step world offsets after model `size` scaling so all entity sizes travel exact tile distances.
